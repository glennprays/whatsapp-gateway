# Changelog

All notable changes to this project are documented here. Versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **Group & community mutations (Phase E)** — the highest-ban-risk feature group, shipped default-safe. New group endpoints: `POST /api/group/` (create group/community), `POST /api/group/leave`, `POST /api/group/participants` (`action`=add/remove/promote/demote), `PATCH /api/group/settings` (announce/locked), `PATCH /api/group/name` (≤25), `PATCH /api/group/topic` (≤512), `PUT`/`DELETE /api/group/photo` (multipart JPEG / clear), `GET /api/group/invite` + `POST /api/group/invite/reset` (admin invite link), `GET /api/group/invite/info?code=` (preview without joining), `POST /api/group/join` (join via link), `GET`/`POST /api/group/requests` (list / approve-reject pending join requests); new community endpoints `POST`/`DELETE /api/community/subgroups` (link/unlink a sub-group). Every group op requires an **explicit `@g.us`** JID (a bare number or user JID is a 400 — a group op never lands on a user). Batch mutations return **200 partial success** with per-participant `results[]` (privacy-blocked add → `invited` + invite code/expiry; non-member promote → `failed` + code), never an overall error for one bad member. Removing/promoting/demoting your own number is a 400 (use leave). **Ban-safety gates** (default): the whole mutation/invite/join-request/community surface is behind `GROUP_MANAGEMENT_ENABLED` (default `true`; when `false` the routes are unregistered → `404`, reads stay up); **bulk participant add** + add-on-create are gated by `GROUP_ADD_PARTICIPANTS_ENABLED` (default `false` → `403`), and **join-via-link (mass join)** by `GROUP_JOIN_VIA_LINK_ENABLED` (default `false` → `403`); `GROUP_MAX_PARTICIPANTS_PER_REQUEST` caps a batch (default `256`). New `410 Gone` mapping for a revoked invite link. `openapi.yaml` → `0.22.0`.
- **Operator visibility (Phase D)** — a new operator-only admin plane at the ROOT path (outside `/api/v1`), dark by default. `GET /admin/sessions` returns a per-instance inventory of every account this node knows about, merged from the in-memory client set, the whatsmeow device store, and a new persisted `session_status` table into honest states (`connected` / `disconnected` / `never_paired` / `logged_out` / `banned`), each with a `source` (`in-memory` / `store`), masked phone, and the reporting `instance` (hostname). `GET /admin/sessions/{phone}` returns one account or `404`. Both are gated by `ADMIN_API_SECRET`: unset ⇒ the routes are never registered (`404`, never a `401` that would confirm the plane exists); set ⇒ `Authorization: Bearer <secret>` compared in constant time (`crypto/subtle`). Cross-tenant by design (operator-only). `openapi.yaml` → `0.21.0`.
- **Session lifecycle tracking** — whatsmeow `LoggedOut` / `TemporaryBan` / `ConnectFailure` / `StreamReplaced` events now persist the account's state to `session_status` (no FK to `whatsmeow_device`, so a logged-out/banned record survives whatsmeow deleting the device row) and evict the dead in-memory client. A *transient* `ConnectFailure` (not logged-out) is recorded as `disconnected` but **not** evicted, so auto-reconnect can recover it. An unexpired temporary ban carries `ban_expires_at`; an expired ban reads back as `disconnected`.
- **`GET /metrics`** — hand-rolled Prometheus text exposition (no new dependency) gated by `METRICS_ENABLED` (default `false`) **and** the admin bearer. Series: `whatsapp_gateway_messages_total{type,mode,result}`, `whatsapp_gateway_webhook_deliveries_total{result,mode,event}`, and a scrape-computed `whatsapp_gateway_sessions{state}` gauge. Cardinality is bounded by construction — a phone number is **never** a label (per-account detail lives on `/admin/sessions` instead).
- **Direct-mode webhook retry parity** — direct-mode status webhooks (`message.queued` / `message.sent` / `message.failed`) are now delivered asynchronously with bounded exponential backoff on a detached context (so a retry outlives the HTTP request), semaphore-bounded and drop-on-full. Tuned by `WEBHOOK_MAX_RETRIES` (default 3) and `WEBHOOK_RETRY_BACKOFF_SECONDS` (default 2). Queue mode keeps RabbitMQ-level retry (not double-retried). Best-effort; durable delivery still requires RabbitMQ.
- **Replies & mentions on every send** — all `POST /api/message/*` sends (text, image, audio, video, document, location, poll, sticker) now accept `reply_to_id` + `reply_to_sender` (+ optional `reply_to_text` for the quoted preview) to quote a message, and `mentions[]` (numbers/JIDs) to @-tag recipients. Storeless per design (caller supplies the quoted context); the reply/mention `ContextInfo` is attached to the inner media message before any view-once wrap, and to the poll body only (never its `MessageContextInfo`, which carries the vote-decryption secret). On multipart endpoints send `mentions` as **repeated** form fields (not comma-joined). Works in both direct and queue modes.
- **`POST /api/message/read`** — mark messages as read (blue ticks) for a chat: `{chat, message_ids[], sender?}`. `sender` (the message author) is required for group chats. Exactly one whatsmeow receipt type is used, avoiding its multi-type panic.
- **`POST /api/chat/presence`** — typing indicator: `{chat, state}` where `state` is `composing` (typing…), `recording` (voice note; sent as composing+audio), or `paused`. The indicator auto-expires client-side, so an explicit `paused` is optional.
- **Interim per-account action cap** on mark-read / typing (and reusable for react) — reuses the existing limiter under an `action:` key so conversation actions can't be spammed until roadmap #2 pacing lands. Over-budget returns `429`.
- **Send idempotency** via an optional `Idempotency-Key` request header on `/api/message/*`. Backed by a DB table keyed `(phone_number, key)` (phone from the JWT, never the body), checked before the queue/direct fork so it covers both send modes and survives restarts. A duplicate replays the original response verbatim with `Idempotent-Replay: true`; an in-flight duplicate gets `409`; reusing a key with a **different** body gets `422`. In queue mode this guarantees enqueued-once, **not** delivered-once. Retention/behaviour tuned by `IDEMPOTENCY_TTL_SECONDS` (default 24h) and `IDEMPOTENCY_PENDING_TIMEOUT_SECONDS` (default 30s); a background sweeper bounds table growth.
- **Unified `chat` recipient** on every send/message/contact-check request. `chat` accepts a bare phone number, a user JID (`@s.whatsapp.net`), a group JID (`@g.us`), or a `@lid`, so groups are now addressable. Send responses echo the resolved canonical `chat` JID. First step of the automation-platform plan (`docs/plan/`).
- **Graceful multi-account shutdown**: all whatsmeow clients are now disconnected cleanly on shutdown (before the DB closes), concurrently and bounded by `SHUTDOWN_CLIENT_DISCONNECT_TIMEOUT_SECONDS` (default 10), so deploys no longer drop sockets abruptly.
- **Liveness/readiness probes** at the root path: `GET /health/live` (always `200`, process-only) and `GET /health/ready` (`503` when the DB or an enabled queue is down; deliberately not coupled to WhatsApp session health). The existing `/health` under the API base path is unchanged.
- **`GET /api/contact/`** — list the account's locally-synced contacts, paginated via `limit`/`offset` (default 100, max 500), with `count`/`total` and a synced-state note. A pure local-store read (no network); an empty/partial list right after pairing is normal, not an error.
- **`GET /api/group/`** — list the account's joined groups (lightweight summaries: jid, name, topic, owner, participant count, announce/locked/community flags). Hits the WhatsApp server, so it is short-TTL cached and metered by a per-account **read budget** (`READ_QUERY_*`); repeat polls are served from cache, and an exhausted budget returns `429`.
- **Read/query cache + per-account budget** infra (`READ_QUERY_CACHE_TTL_SECONDS`, `READ_QUERY_BUDGET`, `READ_QUERY_WINDOW_SECONDS`) shared by all server-hitting reads so polling can't trip anti-spam.
- **`GET /api/group/info?chat=<@g.us>`** — full detail of one group incl. the participant roster (jid/phone/lid + admin flags). Requires a group JID and account membership. Cached + budgeted.
- **`GET /api/contact/info?chat=`** — server-side profile lookup for one user (status text, current picture id, verified business name, linked-device count, lid). Cached + budgeted.
- **whatsmeow error sentinels mapped via `errors.Is`** (not substring): `ErrGroupNotFound`/`ErrProfilePictureNotSet` → `404`, `ErrNotInGroup`/`ErrProfilePictureUnauthorized` → `403`.
- **`GET /api/community/subgroups?chat=<@g.us>`** and **`GET /api/community/participants?chat=<@g.us>`** — read a community's linked sub-groups (whatsmeow `GetSubGroups`) and all participants across its linked groups (`GetLinkedGroupsParticipants`). Both take the community's `@g.us` JID and ride the same short-TTL cache + per-account **read budget** as the other group reads (`429` when exhausted); a community with zero sub-groups returns an empty list, not an error. Unlike `group/info`, these whatsmeow calls surface a raw IQ error, so a non-community group (or absence) is mapped to `400`/`403`/`404` by IQ code via a new `errors.As(*IQError)` branch in the error mapper. `openapi.yaml` (version → `0.20.0`) / `llms.txt` document both under a new `Community` tag.
- **`GET /api/contact/avatar?chat=`** — a chat's (user or group) profile picture: a time-limited CDN URL plus its id. `?preview=true` for the thumbnail. Tri-state — `404` (no picture), `403` (hidden from you), `200` otherwise. The id doubles as an `ETag`: send it back via `If-None-Match` to get `304 Not Modified` when unchanged (the freshness check bypasses the cache but still spends read budget). Cached + budgeted like other server reads.

### Changed
- `msisdn` is now a **deprecated back-compat alias** for `chat` (still fully supported; `chat` wins when both are set). Recipient resolution funnels through `resolveChat`, which strips device/agent JID suffixes, lowercases the server, requires a digits-only user, and rejects `broadcast`/unknown servers early with a `400` instead of a late `500`.
- `openapi.yaml` / `llms.txt`: `chat` added to all request bodies + send responses; `msisdn` marked deprecated and dropped from `required`; read endpoints documented (`GET /contact/`, `GET /contact/info`, `GET /contact/avatar`, `GET /group/`, `GET /group/info`) with their schemas; `Idempotency-Key` header + `409`/`422` responses added to every `POST /message/*` send (reusable `IdempotencyKeyHeader` parameter); `POST /message/read` + `POST /chat/presence` documented with their schemas; `reply_to_*` + `mentions` added to all seven send schemas (text, image, audio, video, document, location, poll, sticker); `Contact`/`Group` tags added; version → `0.19.0`.

## [0.11.0] - 2026-07-05

### Added
- `POST /message/audio` (voice notes via `is_ptt`; view-once).
- `POST /message/video` (caption, `is_gif`, view-once).
- `POST /message/document` (`file_name`, caption wrapped for reliable render).
- `GET /contact/check` — `IsOnWhatsApp` recipient validation; warms the LID↔PN cache.
- Outbound media size cap (`MAX_UPLOAD_BYTES`) + per-kind MIME allow-lists.
- Per-IP rate limit on `POST /register` (`REGISTER_RATE_LIMIT_*`).

### Fixed
- Polls now decryptable (`BuildPollCreation` injects MessageSecret — polls were write-only).
- Reactions attribute correctly (`BuildReaction` + optional `sender_msisdn`).
- `@lid` no longer leaks into webhook `from` (prefer `SenderAlt`; new `addressing_mode` field).
- `JWT_TOKEN_DURATION_MINUTES` overflow clamped to 1..525600.
